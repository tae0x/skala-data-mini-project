## 1. 분류와 평가 (아는 것에서 출발)

### 1.1 혼동행렬

모델이 "독성 없음(1)"이라고 예측하는 걸 **양성(Positive)**이라고 부릅니다. 네 가지 결과가 나옵니다.

| | 실제 독성 없음(1) | 실제 독성 있음(0) |
|---|---|---|
| **1이라고 예측** | TP (맞게 찾음) | **FP (틀리게 찾음)** |
| **0이라고 예측** | FN (놓침) | TN (맞게 제외) |

- **precision(정밀도) = TP / (TP + FP)**: "1이라고 한 것 중 진짜 1인 비율"
- **recall(재현율) = TP / (TP + FN)**: "진짜 1 중에서 내가 찾아낸 비율"
- **F1 = 2 × precision × recall / (precision + recall)**: 둘의 균형 점수. 둘 중 하나가 낮으면 F1도 크게 떨어집니다(조화평균).
- accuracy(정확도) = (TP + TN) / 전체

**우리 프로젝트에서는**: Positive가 "독성 없음"입니다. 그래서 **FP는 "독성이 있는데 없다고 말한 것"**이고, 신약 개발에서는 가장 위험한 실수입니다. precision이 이 실수를 벌주는 지표입니다.

**헷갈리기 쉬운 점**: 일반적으로 "Positive = 문제가 있는 쪽"으로 생각하기 쉽지만, 이 데이터는 반대입니다. 지표를 읽을 때마다 "Positive가 뭐였지?"를 먼저 확인하세요.

### 1.2 직접 계산해 보기: "전부 1"이라고 찍으면

8,349개 중 실제 독성 없음 4,542개, 독성 있음 3,807개입니다. 전부 1이라고 하면:

| | 실제 1 | 실제 0 |
|---|---|---|
| 1이라고 예측 | TP = 4,542 | FP = 3,807 |
| 0이라고 예측 | FN = 0 | TN = 0 |

- precision = 4,542 / 8,349 = **0.544**
- recall = 4,542 / 4,542 = **1.000** (다 1이라고 했으니 안 놓침)
- F1 = 2 × 0.544 × 1.000 / 1.544 = **0.705**
- accuracy = 0.544

아무 생각 없이 찍어도 F1이 0.705입니다. 이 점수가 **기준선(baseline)**입니다. 기준선을 모르면 "F1 0.72가 나왔다"가 좋은 건지 알 수 없습니다.

반대로 전부 0이라고 하면 TP가 0이라 recall = 0, F1 = 0입니다.

### 1.3 precision과 recall은 서로 밀고 당깁니다

`clogp`가 낮을수록 독성 없음 쪽이라서, "clogp가 기준값보다 낮으면 1"이라는 규칙을 만들어 봤습니다. 기준값을 바꿔 가며 직접 계산한 결과입니다.

| 규칙 | TP | FP | FN | TN | precision | recall | F1 |
|---|---|---|---|---|---|---|---|
| clogp < 2.5 (엄격) | 1,119 | 290 | 3,423 | 3,517 | **0.794** | 0.246 | 0.376 |
| clogp < 4.5 | 3,574 | 2,321 | 968 | 1,486 | 0.606 | 0.787 | 0.685 |
| clogp ≤ 5.99 (거의 다 1로) | 4,386 | 3,478 | 156 | 329 | 0.558 | **0.966** | 0.707 |

- 엄격하게 하면 precision은 오르지만(0.794) 놓치는 게 많아져 recall이 폭락합니다(0.246). F1은 0.376으로 기준선보다 훨씬 낮습니다.
- F1이 가장 높은 기준값은 약 5.99로, 사실상 거의 다 1이라고 찍는 규칙이고 F1은 **0.707로 기준선(0.705)과 거의 같습니다.**
- 의미: **clogp 하나만으로는 기준선을 거의 못 넘습니다.** 그래서 변수를 여러 개 합치는 모델이 필요합니다.

### 1.4 왜 accuracy가 아니라 F1인가

정답이 한쪽으로 쏠린 데이터에서는 accuracy가 속이기 쉽습니다(예: 99%가 정상이면 전부 정상이라고 해도 accuracy 99%). 이 과제는 교수님이 F1을 주 지표로 정했습니다. 우리 데이터는 54.4 대 45.6으로 많이 쏠리진 않았지만, "전부 1"이 F1 0.705가 되는 것처럼 Positive 비율이 높으면 F1도 쉽게 높아집니다.

## 2. 화학 데이터 읽기

| 용어 | 한 줄 설명 | 비유 |
|---|---|---|
| **SMILES** | 분자 구조를 한 줄 글자로 적은 표기. 예: 물 `O`, 이산화탄소 `O=C=O` | 분자의 주민등록 이름 |
| **분자 핑거프린트** | 분자에 어떤 구조 조각이 있는지를 0/1 1,024칸으로 표시한 것 | 체크리스트(있다 1, 없다 0) |
| `ecfp` | 각 원자 주변이 어떤 구조인지 보는 지문(구조 유사성 비교용) | 동네 지도 |
| `fcfp` | 원자의 기능적 역할(수소결합을 주는지 등) 중심의 지문 | 직업 기준 지도 |
| `ptfp` | 화학자들이 자주 쓰는 부분구조 패턴이 있는지 보는 지문 | 자주 나오는 모양 도장 |
| `MolWt` | 분자량. 분자의 무게 | 몸무게 |
| `clogp` | **계산한 logP.** 물과 기름 중 어디에 더 잘 녹는지. 클수록 기름에 잘 녹음(지용성) | 기름 친화도 |
| `TPSA` (RDKit 파생) | 극성 표면적. 물과 친한 부분이 얼마나 넓은지 | 물과 친한 면적 |
| `NOCount` (RDKit 파생) | 질소(N)와 산소(O) 원자의 수 | N, O 개수 |
| `qed` | 약물 유사성 점수(0~1). 약으로 쓰이는 분자들과 얼마나 닮았나 | 약 같은 정도 |
| `sa_score` | 합성 난이도(1 = 쉬움, 10 = 어려움) | 만들기 어려운 정도 |
| **RDKit** | SMILES로부터 위 수치들을 계산해 주는 파이썬 도구 | 계산기 |

**우리 프로젝트에서는**: 핑거프린트는 3,072칸이라 칸 하나하나의 의미를 해석하기 어렵습니다. 반면 `clogp`, `TPSA` 같은 수치는 화학적으로 해석이 됩니다(그래서 발표에서 인사이트로 쓰기 좋았습니다).

**헷갈리기 쉬운 점**:
- 기존 열 `MolWt`, `clogp`, `qed`는 RDKit이 계산하는 값과 사실상 같습니다(상관 1.0). 그래서 파생변수를 만들 때 중복으로 뺐습니다. `sa_score`만 RDKit 기본 기술자에 없어서 남았습니다.
- `ecfp`의 "e"가 extended라서 무엇이 확장됐는지 헷갈릴 수 있는데, 원자 주변을 점점 넓혀 가며 구조를 보기 때문입니다. 칸 번호(`ecfp_807`)는 특정 구조를 가리키지만, 어느 구조인지는 별도 분석 없이는 모릅니다.

## 3. EDA가 하는 일

**EDA(탐색적 데이터 분석)**는 모델을 만들기 전에 데이터를 열어서 "어떻게 생겼는지, 문제는 없는지, 단서는 있는지"를 보는 단계입니다. 요리 전에 재료를 살펴보는 것과 같습니다.

| 개념 | 한 줄 정의 | 왜 보나 | 우리 결과 |
|---|---|---|---|
| 결측값 | 비어 있는 칸 | 많으면 채우거나 버려야 함 | 0개 |
| 중복 | 같은 행이 여러 번 | 같은 문제가 시험과 학습에 모두 들어가 점수가 부풀 수 있음 | SMILES 중복 0개 |
| 분포 | 값이 어디에 얼마나 몰려 있나(히스토그램) | 치우쳤는지 확인 | 대체로 종 모양 |
| 평균과 중앙값 | 평균은 합/개수, 중앙값은 한가운데 값 | 둘이 많이 다르면 치우침 | 거의 같음(MolWt 443.2 / 441.5) |
| 왜도 | 한쪽으로 늘어진 정도(0이면 대칭) | 로그 변환 필요 여부 | 가장 큰 `sa_score`가 0.89 |
| 이상치 | 다른 값들과 동떨어진 값 | 모델을 흔들 수 있음 | MolWt, clogp, sa_score는 1.6~1.9%, qed는 0건. 처리는 Day2 |
| 상관 | 두 변수가 같이 움직이는 정도(-1~1) | 겹치는 정보 찾기 | MolWt와 qed가 -0.76 |
| 다중공선성 | 설명 변수끼리 너무 비슷함 | 선형 모델이 불안정해질 수 있음 | RDKit 파생변수 66쌍이 0.95 초과 |
| 클래스 불균형 | 정답 종류의 비율 차이 | 지표 선택에 영향 | 54.4 대 45.6 (크지 않음) |
| 상수열 | 모든 행이 같은 값인 열 | 정보가 없음 | `ptfp` 49개 |

**헷갈리기 쉬운 점**: 상관이 높다고 같은 변수는 아닙니다. 하지만 정보가 많이 겹치므로 둘 다 넣어도 새로 얻는 게 적을 수 있습니다. 그리고 상관은 "함께 움직임"일 뿐 "원인"이 아닙니다.

## 4. "이 변수가 정답을 얼마나 설명하나"를 재는 법

이번 EDA의 핵심입니다. 3,231개 열을 **같은 잣대**로 비교했습니다.

### 4.1 AUC

- **정의**: 정답이 1인 행 하나와 0인 행 하나를 무작위로 뽑았을 때, 이 변수 값이 1인 행 쪽이 더 높을 확률.
- **0.5**면 동전 던지기와 같고(변수가 아무것도 모름), **1.0**이면 완벽하게 가릅니다. 0.5보다 작으면 방향이 반대라는 뜻입니다.
- 우리 결과: `clogp`는 AUC 0.3375입니다. 0.5보다 작으니 "값이 낮을수록 1(독성 없음)"입니다. 방향을 뒤집으면 0.6625입니다.

### 4.2 Gini = |2 × AUC − 1|

- AUC를 0~1의 "설명력 점수"로 바꾼 것입니다. 0이면 설명 못함, 1이면 완벽.
- `clogp`: |2 × 0.3375 − 1| = **0.325**. `MolWt`: AUC 0.495이므로 Gini **0.011**(사실상 0).
- 핑거프린트 칸(0 또는 1)에서는 "독성 없음(1) 그룹에서 그 칸이 켜진 비율 − 독성 있음(0) 그룹에서 그 칸이 켜진 비율"의 절댓값과 같습니다(|TPR − FPR|). 예: `ecfp_807`은 71.6% − 53.3% = 0.183입니다. 그래서 연속형 변수와 핑거프린트를 한 줄로 세울 수 있었습니다.

### 4.3 p-value와 효과 크기는 다릅니다

- **p-value**: "사실은 차이가 없다고 가정했을 때, 이 정도 차이가 우연히 나올 확률". 작을수록 "우연은 아니다"라는 뜻입니다.
- **효과 크기**(Cohen's d, Gini 등): "차이가 얼마나 큰가".
- **표본이 8,349개로 크면 아주 작은 차이도 p가 작아집니다.** `qed`와 `sa_score`는 p가 매우 작지만 Gini가 0.097, 0.083으로 작습니다. 그래서 "유의하다"와 "설명력이 크다"를 구분해야 합니다. 보고서에서 "유의한 비트 1,286개"와 "Gini 최대 0.18"을 같이 쓴 이유입니다.

### 4.4 다중검정과 FDR

- 검정을 3,231번 하면, 실제로는 아무 관계가 없어도 **유의 수준 5%에서 약 160개(3,231 × 0.05)가 우연히 "유의"로 나옵니다.**
- **FDR(Benjamini-Hochberg)** 보정은 이 우연을 감안해 p값을 엄격하게 고치는 방법입니다. 우리는 보정 후에도 1,428개가 유의했습니다(q < 0.05).

**헷갈리기 쉬운 점**: Gini가 0.3이라고 모델 성능이 0.3이라는 뜻이 아닙니다. 변수 하나씩의 점수일 뿐이고, 합쳤을 때의 성능은 따로 재야 합니다.

## 5. 데이터 분할과 누수

### 5.1 왜 나누나

시험공부를 하는 학생에게 시험 문제를 미리 보여 주면 점수가 높아도 실력을 알 수 없습니다. 같은 이유로 데이터를 **학습용(train)**과 **시험용(test)**으로 나눕니다. 시험용은 모델이 한 번도 보지 못한 상태로 두었다가 마지막에 한 번만 씁니다.

### 5.2 stratify

나눌 때 정답 비율(54.4 대 45.6)이 학습용과 시험용에서 같게 유지되도록 하는 옵션입니다(`stratify=y`).

### 5.3 교차검증 (K-Fold)

학습용을 5조각으로 나눠서, 4조각으로 공부하고 1조각으로 시험보는 것을 5번 돌려 평균을 냅니다. 운 좋게 쉬운 문제가 걸리는 것을 막아 줍니다.

### 5.4 데이터 누수 (data leakage)

- **정의**: 시험용 정보가 학습 과정에 몰래 섞이는 것.
- **예**: 전체 데이터의 평균으로 빈칸을 채운 뒤에 나누면, 시험용 정보가 평균에 들어갑니다. 그래서 **나누기를 먼저 하고, 평균이나 크기 맞춤 기준은 학습용에서만 계산**합니다.

**우리 프로젝트에서는**: 이번 EDA의 설명력(Gini 등)은 **전체 train 데이터로 계산한 탐색용**입니다. 모델 점수를 매긴 게 아니라서 큰 문제는 아니지만, "어떤 변수를 쓸지" 고르는 일을 이 결과로 확정하면 누수가 됩니다. 그래서 Day2에서 분할한 뒤 학습용으로 다시 합니다. 보고서 8절의 한계에 적어 둔 내용입니다.

| **결정트리** | "clogp < 3.5인가?" 같은 질문을 이어 가며 분류 | 스무고개 |
| **랜덤포레스트** | 서로 다른 결정트리 수백 개의 다수결 | 여러 전문가의 투표 |
| **부스팅** (XGBoost, LightGBM, CatBoost) | 트리를 차례로 만들며 앞 트리가 틀린 것을 다음 트리가 보완 | 오답노트로 약점을 메우며 공부 |

- **과적합(overfitting)**: 학습 데이터를 문제와 답까지 외워서 학습 점수는 높고 처음 보는 데이터에서는 낮은 상태. 교차검증과 시험용 데이터로 잡아냅니다.
- **하이퍼파라미터**: 모델이 스스로 배우지 않고 사람이 정하는 설정(트리 개수, 깊이 등). **튜닝**은 이 설정을 찾는 일이고 Optuna 같은 도구가 자동으로 탐색합니다.
- **앙상블**: 여러 모델의 예측을 합쳐서 더 안정적인 예측을 만드는 것.
- **기준선 모델**: 단순한 방법으로 점수를 먼저 잡아 두는 것. 복잡한 모델이 이걸 얼마나 넘는지로 가치를 판단합니다.

**우리 프로젝트에서는**: 열이 3,000개가 넘고 행은 8,349개뿐이라 열이 훨씬 많은 데이터입니다. 이런 데이터에서는 과적합 위험이 커서 교차검증이 특히 중요합니다.

---

## 8. 해석: 왜 그렇게 예측했나

- **변수 중요도**: 모델이 예측할 때 어떤 변수를 많이 썼는지 순위로 보는 것.
- **Permutation Importance**: 변수 하나의 값을 무작위로 섞었을 때 점수가 얼마나 떨어지는지로 중요도를 재는 방법. 많이 떨어지면 중요한 변수입니다.
- **SHAP**: 개별 예측에서 "각 변수가 이 예측을 얼마나 올리고 내렸는지"를 계산해 보여 주는 방법. 특정 화합물이 왜 독성 없음으로 예측됐는지 설명할 수 있습니다.

**우리 프로젝트에서는**: Day2에서 SHAP 결과가 이번 EDA의 순위(`clogp`, `TPSA` 등)와 비슷한지 비교하는 게 좋은 마무리가 됩니다.

### 정답

2. 1.000 (진짜 1 4,542개를 전부 1이라고 했으므로).

4. 0. TP가 0이라 recall이 0이다.
5. 정답 1의 비율이 54.4%라서, 전부 1이라고 하면 그 비율만큼 맞는다.
